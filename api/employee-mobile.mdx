Endpoints used by the Employee Mobile App for self-service scheduling, availability, open shifts, push notifications, and calendar sync.

Base prefix: `/chefos/api/v1`

---

## Employee Identity

### `GET /scheduling/me`

Returns the current authenticated user's employee record. The mobile app should call this on launch to resolve the employee ID.

**Permission:** `scheduling.profile.read`

**Response:**

```json
{
  "id": "emp_a1b2c3d4",
  "firstName": "Maria",
  "lastName": "Garcia",
  "email": "maria.garcia@restaurant.com",
  "phone": "555-0101",
  "cell": "555-0102",
  "status": "active",
  "role": "employee",
  "employeeNumber": "EMP-042",
  "maxHoursPerWeek": 40,
  "maxDaysPerWeek": 5,
  "locationId": "loc_abc123",
  "positions": [
    { "id": "pos_line_cook", "name": "Line Cook", "color": "#4CAF50" }
  ]
}
```

## My Schedule

### `GET /employee-self-service/upcoming-shifts`

Optimized endpoint for the mobile home screen. Returns the current user's shifts for the next N days.

**Query params:**

| Param | Type | Default | Description |
|---|---|---|---|
| `days` | integer | `7` | Days ahead to fetch (1--30) |

**Permission:** `scheduling.shifts.read` (self-service)

**Response:**

```json
[
  {
    "id": "shift_001",
    "shiftDate": "2026-03-09T00:00:00.000Z",
    "startTime": "1970-01-01T14:00:00.000Z",
    "endTime": "1970-01-01T22:00:00.000Z",
    "status": "published",
    "position": { "id": "pos_line_cook", "name": "Line Cook", "color": "#4CAF50" },
    "station": { "id": "station_grill", "name": "Grill" },
    "isPublished": true
  }
]
```

### `GET /scheduling/shifts`

Full shift list with flexible filtering. Used for the schedule calendar view.

**Query params:**

| Param | Type | Description |
|---|---|---|
| `startDate` | `YYYY-MM-DD` | Filter shifts on or after this date |
| `endDate` | `YYYY-MM-DD` | Filter shifts on or before this date |
| `employeeId` | UUID | Filter by employee |
| `positionId` | UUID | Filter by position |
| `status` | string | `draft` or `published` |

**Permission:** `scheduling.shifts.read`

**Headers:** `X-Location-Id` required.

### `GET /scheduling/weeks`

Check whether schedule weeks are published.

**Query params:**

| Param | Type | Description |
|---|---|---|
| `weekStarts` | string | Comma-separated week start dates (`YYYY-MM-DD`, Sunday-based) |

**Permission:** `scheduling.shifts.read`

**Response:**

```json
[
  { "weekStart": "2026-03-08T00:00:00.000Z", "isPublished": true, "publishedAt": "2026-03-05T16:00:00.000Z" },
  { "weekStart": "2026-03-15T00:00:00.000Z", "isPublished": false, "publishedAt": null }
]
```

### `GET /scheduling/schedule-bootstrap`

Single-call bulk data load for the schedule view. Returns shifts, employees, positions, and time-off requests.

**Query params:**

| Param | Type | Required | Description |
|---|---|---|---|
| `startDate` | `YYYY-MM-DD` | Yes | Start of range |
| `endDate` | `YYYY-MM-DD` | Yes | End of range (max 62 days) |
| `includeReferenceData` | boolean | No | Include employees/positions (default: true) |
| `includeTimeOffRequests` | boolean | No | Include time-off requests (default: true) |

**Permission:** `scheduling.shifts.read`

**Headers:** `X-Location-Id` required.

## Time-Off Management

### `GET /scheduling/time-off-requests`

List time-off requests. Employees see their own; managers see all for the location.

**Query params:**

| Param | Type | Description |
|---|---|---|
| `employeeId` | UUID | Filter by employee (pass own ID for self-service) |
| `status` | string | `pending`, `approved`, `denied`, `cancelled` |
| `startDate` | `YYYY-MM-DD` | Requests overlapping on or after this date |
| `endDate` | `YYYY-MM-DD` | Requests overlapping on or before this date |

**Permission:** `scheduling.time_off.read`

**Headers:** `X-Location-Id` required.

**Response:**

```json
[
  {
    "id": "tor_001",
    "employeeId": "emp_a1b2c3d4",
    "startDate": "2026-03-20T00:00:00.000Z",
    "endDate": "2026-03-21T00:00:00.000Z",
    "reason": "Family event",
    "status": "pending",
    "isPartialDay": false,
    "startTime": null,
    "endTime": null,
    "reviewedBy": null,
    "reviewComment": null
  }
]
```

### `POST /scheduling/time-off-requests`

Submit a new time-off request. The employee is resolved from the authenticated user.

**Request body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `startDate` | `YYYY-MM-DD` | Yes | First day off |
| `endDate` | `YYYY-MM-DD` | Yes | Last day off |
| `reason` | string | No | Reason for the request |
| `isPartialDay` | boolean | No | True for partial-day request |
| `startTime` | `HH:MM` | No | Required if `isPartialDay` |
| `endTime` | `HH:MM` | No | Required if `isPartialDay` |

**Permission:** `scheduling.time_off.write`

**Headers:** `X-Location-Id` required.

### `DELETE /scheduling/time-off-requests/:id`

Cancel an own pending time-off request. Only pending requests can be cancelled.

**Permission:** `scheduling.time_off.write`

### `GET /scheduling/time-off/settings`

Retrieve time-off policy settings (minimum notice, max advance days, approval rules).

**Permission:** `scheduling.settings.read`

**Response:**

```json
{
  "minDaysNotice": 7,
  "maxDaysAdvance": 90,
  "requireManagerApproval": true,
  "autoApproveIfNoConflicts": false
}
```

### `GET /scheduling/time-off/blocked-days`

Retrieve blackout dates when time-off is not allowed.

**Query params:**

| Param | Type | Description |
|---|---|---|
| `startDate` | `YYYY-MM-DD` | Filter blocked days on or after |
| `endDate` | `YYYY-MM-DD` | Filter blocked days on or before |

**Permission:** `scheduling.time_off.read`

**Response:**

```json
[
  {
    "id": "bd_001",
    "date": "2026-03-17T00:00:00.000Z",
    "reason": "St. Patrick's Day - all hands",
    "isFullDay": true
  }
]
```

Get details for a single open shift, including all claims.

```json
  "shiftDate": "2026-03-12T00:00:00.000Z",

      "employeeId": "emp_a1b2c3d4",
      "status": "pending",
      "employee": { "firstName": "Maria", "lastName": "Garcia" }
    }
  ]
}
```

### `POST /scheduling/open-shifts/:id/claim`

Claim an open shift. Creates a pending claim requiring manager approval.

**Request body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `message` | string | No | Optional message to the manager |

**Permission:** `scheduling.shifts.write` (self-service)

**Response:**

```json
{
  "id": "claim_002",
  "shiftId": "shift_open_001",
  "employeeId": "emp_a1b2c3d4",
  "status": "pending",
  "message": "I'm available and qualified for this shift"

```

| Status | Error |
|---|---|
| `400` | Shift is no longer open |
| `400` | You have already claimed this shift |

### `DELETE /scheduling/open-shifts/claims/:claimId`

Withdraw your own pending claim.

**Permission:** `scheduling.shifts.write` (self-service)

## Availability

### `GET /employee-self-service/availability`

Get the current employee's weekly availability slots.

**Permission:** `scheduling.profile.read` (self-service)

**Response:**

```json
[
  {
    "id": "avail_001",
    "dayOfWeek": 1,
    "startTime": "08:00",
    "endTime": "16:00",
    "isAvailable": true,
    "effectiveFrom": "2026-03-01",
    "effectiveUntil": null,
    "notes": null
  }
]
```

**Day of week values:** 0 = Sunday, 1 = Monday, 2 = Tuesday, 3 = Wednesday, 4 = Thursday, 5 = Friday, 6 = Saturday.

### `PUT /employee-self-service/availability`

Replace all availability slots with a new set. This is a full replacement -- all existing slots are deleted and replaced.

**Request body:**

| Field | Type | Required | Description |
|---|---|---|---|
| `slots` | array | Yes | Array of slot objects |

**Slot object:**

| Field | Type | Required | Description |
|---|---|---|---|
| `dayOfWeek` | integer (0--6) | Yes | Day of week (0 = Sunday) |
| `startTime` | `HH:MM` | Yes | Start of availability window |
| `endTime` | `HH:MM` | Yes | End of availability window |
| `isAvailable` | boolean | No | Default: true. Set false to mark unavailable |
| `notes` | string | No | Optional notes |

**Permission:** `scheduling.profile.write` (self-service)

**Response:**

```json
{ "ok": true, "count": 6 }
```

### `PATCH /employee-self-service/availability/:id`

Update a single availability slot. Only changed fields need to be sent.

**Request body (all optional):**

| Field | Type | Description |
|---|---|---|
| `startTime` | `HH:MM` | New start time |
| `endTime` | `HH:MM` | New end time |
| `isAvailable` | boolean | Availability status |
| `notes` | string | Notes |

**Permission:** `scheduling.profile.write` (self-service)

### `DELETE /employee-self-service/availability/:id`

Delete a single availability slot.

**Permission:** `scheduling.profile.write` (self-service)

## Pagination

List endpoints support optional pagination. When `page` is omitted, the response is a raw JSON array. When `page` is provided, the response is wrapped in an envelope.

**Request params:**

| Param | Type | Default | Description |
|---|---|---|---|
| `page` | number | -- | Page number (1-indexed) |
| `limit` | number | `50` | Items per page (max varies by endpoint, typically 100) |

**Paginated response:**

```json
{
  "data": [ { "..." : "..." } ],
  "pagination": { "page": 1, "limit": 50, "total": 127, "totalPages": 3 }
}
```

Endpoints that support pagination: `/scheduling/shifts`, `/scheduling/trades`, `/scheduling/trade-requests`, `/scheduling/time-off-requests`, `/scheduling/open-shifts`.
