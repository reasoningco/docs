This index lists the developer-facing route groups currently exposed by the ChefOS backend. Every protected endpoint uses the `/api/v1` prefix.

## Fundamentals

| Domain | Endpoints |
|---|---|
| Health | `GET /api/v1/health`, `GET /api/v1/ready`, `GET /api/v1/health/redis` |
| Auth | `POST /api/v1/auth/sign-in`, `POST /api/v1/auth/refresh`, `POST /api/v1/auth/sign-out`, `POST /api/v1/auth/reset-password`, `POST /api/v1/auth/resolve-username`, `GET /api/v1/auth/organizations` |
| MFA | `GET /api/v1/auth/mfa-policy`, `GET /api/v1/auth/2fa/status`, `POST /api/v1/auth/2fa/enroll`, `POST /api/v1/auth/2fa/challenge`, `POST /api/v1/auth/2fa/verify`, `DELETE /api/v1/auth/2fa/unenroll/:factorId` |
| Account context | `GET /api/v1/me/permissions`, `GET /api/v1/me/preferences/widgets`, `PUT /api/v1/me/preferences/widgets`, `GET /api/v1/me/preferences/appearance`, `PUT /api/v1/me/preferences/appearance` |
| Profile | `GET /api/v1/profile`, `PATCH /api/v1/profile`, `PATCH /api/v1/profile/password`, `POST /api/v1/profile/avatar` |

## Internal or limited-access surfaces

Some registered routes are intended for ChefOS staff tools, support, infrastructure, or provider callbacks. They may require separate approval or may not be available to partner API clients.

| Route group | Notes |
|---|---|
| `/api/v1/admin`, `/api/v1/admin-console`, `/api/v1/admin/queues` | Staff and tenant administration |
| `/api/v1/proxy`, `/api/v1/browser` | Controlled browser/proxy tools |
| `/api/v1/demo`, `/api/v1/onboarding` | Demo and signup workflows |
| `/public/bids` | Public vendor bid portal links outside `/api/v1` |
