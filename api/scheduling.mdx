---
title: "Scheduling API"
description: "Use scheduling endpoints for employees, shifts, time off, availability, and labor workflows."
---

Scheduling endpoints support employee roster sync, schedule publishing, templates, time off, availability, meals, manager tasks, and labor reporting.

## Employees and positions

| Endpoint | Use it for |
|---|---|
| `GET /api/v1/scheduling/me` | Resolve the current employee and schedule context |
| `GET /api/v1/scheduling/schedule-bootstrap` | Load schedule bootstrap data |
| `GET /api/v1/scheduling/employees` | List employees |
| `POST /api/v1/scheduling/employees` | Create an employee |
| `GET /api/v1/scheduling/employees/:id` | Read one employee |
| `PATCH /api/v1/scheduling/employees/:id` | Update an employee |
| `DELETE /api/v1/scheduling/employees/:id` | Soft-delete an employee |
| `POST /api/v1/scheduling/employees/:id/restore` | Restore a deleted employee |
| `GET /api/v1/scheduling/employees/deleted` | Read recently deleted employees |
| `GET /api/v1/scheduling/positions` | List schedulable positions |
| `POST /api/v1/scheduling/positions` | Create a position |
| `PATCH /api/v1/scheduling/positions/:id` | Update a position |
| `DELETE /api/v1/scheduling/positions/:id` | Delete a position |
| `GET /api/v1/scheduling/employee-positions` | Read employee-position assignments |
| `PUT /api/v1/scheduling/employees/:id/positions` | Replace employee-position assignments |
| `POST /api/v1/scheduling/employee-positions/toggle` | Toggle one employee-position assignment |
| `PATCH /api/v1/scheduling/employee-positions/pay-rate` | Update position pay rate |

## Required context

Scheduling data is usually location-scoped. Use employee IDs and shift IDs returned by ChefOS when syncing changes.
