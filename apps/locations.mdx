---
title: "Locations use cases"
description: "Model location hierarchy, equipment, stations, maintenance, work orders, inspections, and devices."
---

Use locations when an integration needs to understand where operational data belongs.

| Workflow | APIs to start with |
|---|---|
| Show a user's accessible locations | `GET /api/v1/locations/mine` |
| Sync location hierarchy | `GET /api/v1/locations`, `PATCH /api/v1/locations/:id/parent` |
| Manage equipment assets | `GET /api/v1/locations/assets`, `POST /api/v1/locations/:id/assets` |
| Create maintenance work | `POST /api/v1/locations/assets/:assetId/workorders` |
| Ingest device readings | `POST /api/v1/locations/webhooks/devices/:deviceId` |
| Manage station records | `/api/v1/stations` |

## Integration guidance

Store ChefOS location IDs with the external system's location IDs. Avoid matching by display name after the first setup because names can change.
