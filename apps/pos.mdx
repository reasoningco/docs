---
title: "POS use cases"
description: "Connect checkout, catalog, payments, customer display, refunds, and closeout workflows."
---

ChefOS Register is the POS application in the Web OS. Integrations can use POS APIs for checkout-adjacent workflows and provider sync.

| Workflow | APIs to start with |
|---|---|
| Read sellable catalog data | `GET /api/v1/pos/catalog` |
| Create a sale from an approved register flow | `POST /api/v1/pos/sales` |
| Show recent sales or receipts | `GET /api/v1/pos/sales/recent`, `GET /api/v1/pos/sales/:id/receipt` |
| Connect payment hardware | `GET /api/v1/pos/payments/readers`, `GET /api/v1/pos/payments/connect/status` |
| Read closeout state | `GET /api/v1/pos/shifts/current`, `GET /api/v1/pos/shifts/recent` |
| Sync external POS systems | `/api/v1/integrations/pos/*`, `/api/v1/sales/uploads` |

## Integration guidance

Use server-side calls for sale creation, payment operations, refunds, and provider credentials. Client-side displays should call read-only endpoints through a trusted authenticated session.
