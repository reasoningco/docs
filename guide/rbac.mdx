---
title: "Permissions and scopes"
description: "Understand how ChefOS limits API access by domain, action, and location."
---

ChefOS permissions are intentionally narrow. Organization admins select scopes and location grants when they create a token in Developer Access. A token can be limited to read-only access, specific domains, specific actions, or specific locations.

## Scope shape

Scopes generally follow this shape:

`domain.resource.action`

| Example | Allows |
|---|---|
| `sales.analytics.read` | Read sales reports and summaries |
| `scheduling.shifts.write` | Create or update shifts |
| `inventory.items.read` | Read inventory item records |
| `chat.channels.write` | Create or update messaging channels |

## Developer Access scope catalog

The Developer Access UI shows the supported public API scopes. Common scopes include:

| Domain | Scopes |
|---|---|
| Core | `locations.mine.read` |

ChefOS rejects sensitive internal surfaces for Developer Access tokens, including `admin.*`, `auth.*`, `browser.*`, `demo.*`, `onboarding.*`, `profile.*`, `support.*`, `telemetry.*`, and user-management scopes.

## Location scoping

Many endpoints require a location. If a token can access five locations but the request is for one location, ChefOS evaluates the request against that one location.

Location grants are attached to the token. Use `/api/v1/locations/mine` to confirm the exact locations available before showing location-specific data or attempting writes.

## Recommended scopes

| Integration type | Recommended access |
|---|---|
| BI dashboard | `sales.analytics.read`, `scheduling.reports.read`, and read-only inventory scopes |
| POS connector | `sales.transactions.create`, `sales.uploads.write`, and required sales read scopes |
| Scheduling partner | `scheduling.employees.read`, `scheduling.shifts.read`, and write scopes only when syncing changes |
| Inventory partner | Item, count, recipe, order, receipt, invoice, transfer, vendor, and waste scopes |
| Reporting automation | `reports.schedules.read` and `reports.schedules.write` when it manages scheduled reports |

Start read-only whenever possible, then add write scopes after the integration behavior is confirmed.
