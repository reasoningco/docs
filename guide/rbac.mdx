---
title: "Permissions and scopes"
description: "Understand how ChefOS limits API access by domain, action, and location."
---

ChefOS permissions are intentionally narrow. A token can be limited to read-only access, specific domains, specific actions, or specific locations.

## Permission shape

Permissions generally follow this shape:

`domain.resource.action`

| Example | Allows |
|---|---|
| `sales.reports.read` | Read sales reports and summaries |
| `scheduling.shifts.write` | Create or update shifts |
| `inventory.items.read` | Read inventory item records |
| `messaging.channels.write` | Create or update messaging channels |

## Location scoping

Many endpoints require a location. If a token can access five locations but the request is for one location, ChefOS evaluates the request against that one location.

## Recommended scopes

| Integration type | Recommended access |
|---|---|
| BI dashboard | Read-only sales, labor, and inventory reports |
| POS connector | Sales import write access for approved locations |
| Scheduling partner | Employee and shift read/write access as needed |
| Inventory partner | Item, count, recipe, order, and waste scopes |
| Mobile employee app | Self-service scopes for the current employee |

Start read-only whenever possible, then add write scopes after the integration behavior is confirmed.
