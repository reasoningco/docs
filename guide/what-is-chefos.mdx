---
title: "What is ChefOS?"
description: "Understand the public ChefOS platform model for integrations."
---

ChefOS is a restaurant operations platform. It centralizes the data operators need to run locations: sales, labor, inventory, employee communication, and daily execution.

For developers, ChefOS is an API-backed system of record. Integrations can read operational data, write approved updates, and automate workflows across one or many restaurant locations.

## Platform objects

| Object | What it represents |
|---|---|
| Organization | The restaurant group or operating company |
| Location | A restaurant, store, commissary, or operating unit |
| User | A ChefOS account that can access one or more organizations |
| Employee | A schedulable team member at one or more locations |
| Sales data | Checks, revenue, items sold, POS imports, and performance summaries |
| Schedule | Shifts, positions, availability, time off, and shift changes |
| Inventory | Items, recipes, counts, orders, waste, and vendor data |
| Message | Team communication, notifications, and operational alerts |

## Integration model

Most integrations follow the same pattern:

1. Authenticate with an API token.
2. Choose the organization and location context.
3. Read current ChefOS data.
4. Write only the fields your token is scoped to manage.
5. Store ChefOS IDs in your system so future syncs are deterministic.
